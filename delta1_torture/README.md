# Delta-1 Puzzle Torture, Donaldtrumpo

Independent time-limit-stripped one-byte-ROM experiment on all 19,492 Chess.com puzzles rated 2500+. Does not change the earlier original-ROM grading run.

- Correct **solver move**: the exact expected UCI coordinates appear even briefly on the real four-digit emulated LED. `refresh_display()` observes the digits as the ROM writes them, without waiting for a finalized best move.
- A puzzle is **solved** only after **every solver move** in its solution has flashed during its respective search.
- **Donaldtrumpo (Puzzle Torture only):** first give all 19,492 puzzles at least **99 seconds of actual cumulative emulated search**, unless a complete solve is obtained sooner. No official Donaldtrumpo rating is displayed until every puzzle has qualified. Each qualified-but-unsolved puzzle contributes exactly **one provisional loss** (0) and each fully solved puzzle one win (1). After complete qualification, evaluate the whole *fixed* 19,492-puzzle cohort as one Glicko-1 rating period, starting at 2500 (RD 350). Later puzzle solves flip the existing result from 0 to 1; with a fixed denominator this is mathematically nondecreasing. More search slices never add failures. Ordinary puzzle runs are unaffected.
- Preserve each solve event and ascending cumulative emulated-time distribution. Until the 99-second entire-cohort baseline is achieved, the dashboard shows qualification progress and **no official Donaldtrumpo rating**. Once the baseline is established, subsequent genuine wins update the rating and time-distribution graph.
- A not-yet-qualified unsolved puzzle receives only its **remaining** time to 99 seconds on its next slice, preserving any existing search-state checkpoint. Qualified hard puzzles continue on longer time slices, with the complete F8 CPU/RAM/timer/search state saved between turns. Search time is not falsified for puzzles the adapter cannot correctly set up.
- Four independent cloud shards, up to sixteen physical emulator processes each. Separate GitHub branch, release checkpoints, progress JSON, workflow and PC dashboard.
- Previously blocked FENs with castling rights, en-passant squares or promotion moves are **reopened** by `position_trigger.py`: a chess-legal prior position and a genuine ordinary keypad move recreate the solver position. The exact board, side to move, EP square and rights are checked independently before sending the move to the ROM. The reconstructed predecessor may be synthetic and is **not** claimed to be original game history. A short or momentary displayed solver move is watched before ENTER to capture fast completions. The previously identified 220 castling-ambiguity puzzles are retained as a separately marked, rated cohort. In the ROM, illegal castling consideration is a failed candidate, not a technical error. The ROM appears to queen-promote automatically, so underpromotion coordinates alone are **not** treated as a verified underpromotion win; such puzzles still receive search time and count as unsolved if no verifiable exact solution is obtained.
- The ROM time limit is bypassed through the **single-byte 0x0D2C 0x5C=>0x2B** change. Original ROM checksum is checked at build time.
- Automation is subject to GitHub Actions free compute allowance and service availability, and does not guarantee perpetual execution.

- 2026-10-28 adapter repair: 5,721 previously blocked/technical saved positions passed legal-trigger reconstruction; 54 representative ROM input/search attempts were accepted. This does not guarantee absence of new execution errors; each error must remain auditable and retried without corrupting genuine puzzle results. The 99-second floating-point boundary uses a minimum positive 0.1s slice, preventing false technical errors on a few microseconds of remaining emulated time.
